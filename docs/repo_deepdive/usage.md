# 实践手册：从可读代码到有界实验

[返回索引](README.md)

## 1. 本次实际做了什么

已获取六个公开仓库的 star/活动快照，固定源码 commit，读取入口、核心模块、配置与路径，制作源码映射和可离线演示。没有安装这些研究包，没有执行其中生成代码，没有调用付费模型，也没有复现其论文实验。

可直接使用的是各篇的版本固定命令、依赖清单、运行入口和实验设计；它们不伪装成已经在用户机器跑通的记录。

## 2. 统一起步流程

```text
确认许可与适用任务
  -> clone并固定commit
  -> 阅读实际入口与配置
  -> 静态/配置/单位测试
  -> 准备独立模型与执行环境
  -> 最小无破坏任务与资源上限
  -> 完整运行记录
  -> 冻结候选
  -> 独立确认
```

## 3. 每个项目的优先起步点

| 项目 | 优先起步 | 先不要做 |
|---|---|---|
| GenericAgent | 测试目录内的文件/浏览器任务、固定模型 | 真实付款、不可逆操作、无边界终端权限 |
| GEPA | 小型 evaluator 与有限 metric budget | 反复用最终测试挑候选 |
| SoL-Pi | 固定兼容Pi、先测本地机制、逐开关消融 | 一次全开后把收益归因任一单组件 |
| HyperAgents | 小domain、审查容器/权限、预算与存档 | 将生成代码直接放在可信主机执行 |
| RRSI | 固定benchmark、成本口径、STOP与失败阈值 | 为通过候选事后调整guard |
| OpenRSI | 配置/scheduler验证，再准备sandbox和任务包 | 把model自报score当权威反馈，混淆ERL与Evo |

## 4. 应保存的实践记录

- 输入和任务集合、划分与来源。
- 代码 commit、模型/工具/runtime/evaluator 版本。
- flags、实际入口、候选与父代/经验的关系。
- 全部提案、拒绝、失败、超时、unknown 和资源开销。
- 最终选择规则及冻结的产物。
- 新任务/新模型上的确认，与开发反馈分开。

模板是本文建议，不能据此宣称六个项目都已保存这些字段。

## 5. 低成本验证优先级

1. 验证源文件存在、行号和符号与固定 commit 一致。
2. 解析配置和检查必需依赖；不要用缺依赖时的静默默认值掩盖问题。
3. 运行仓库明确提供的最小测试，再考虑外部 API。
4. 使用不含敏感资料的小型合成输入。
5. 真正需要模型运行时，声明预算和停止条件，检查产生的原始证据。

具体仓库命令与 caveat 见[六篇案例](README.md)。不要直接照抄不同仓库的环境变量或运行脚本混用。
