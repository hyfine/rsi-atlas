# 流程读法：主路径、条件与失败

[返回索引](README.md) · [六条动态路径](implementation-atlas.html)

## 1. 为什么动态图不伪造一次运行

动态图展示代码与机制的阅读路径，不生成虚构分数、候选数量、成本或“当前训练中”的假状态。每一步都可以跳转到固定 commit 的源文件。

架构依赖、程序调用、时间先后和反馈回流是四种不同关系；图中文字说明各自语义。循环箭头只表示可能继续，不表示每轮必然进步。

## 2. 六条路径的关键条件

| 项目 | 主路径 | 条件/替代路径 | 重要停止或失败 |
|---|---|---|---|
| GenericAgent | 初始化→模型turn→工具→观察→继续 | browser、provider、历史压缩、兼容入口 | 用户停止、模型/工具失败、循环/上下文限制 |
| GEPA | seed→评估→选父→反思变异→再评估→更新状态 | 通用文本 API、可选 merge、不同 adapters | 预算/停止条件、无效候选、评价异常 |
| SoL-Pi | extension加载→配置→按flags注册→Pi事件 | 四机制各自触发，不是固定四级流水线 | 禁用、校验失败保留原观察、经济条件不满足 |
| HyperAgents | archive→默认选父→patch→容器执行→domain→存档 | 可编辑/容器选择、ensemble | 无有效父代、生成/执行失败、无完整评价 |
| RRSI | history→analyst→proposal→critic→执行→judge→winner | domain guards、不同外部 runner | STOP、连续基础设施失败、低于floor或超成本 |
| OpenRSI | Hydra→执行模式→候选→sandbox→score→状态/恢复 | MLE/NatureBench、同步/异步、不同资源池 | 外部服务失败、预算、无有效提交、恢复边界 |

详细条件及代码行以各[案例章节](README.md)的源码表为准；本表不是替代实现规格。

## 3. 从流程转成实践检查

1. 先选择一个实际入口，而不是同时混用所有示例配置。
2. 记录输入、模型与评价协议，确定哪些字段可被候选改动。
3. 保留第一次失败的日志、状态和费用；重试要有明确上限。
4. 检查 result/receipt 是否确实消费了原始执行结果。
5. 恢复需要说明恢复了哪些状态，而非只复用 output 目录名称。
6. 最终产物冻结后再看新任务；不要反复打开最终答案指导搜索。

## 4. 继续与停止的科学含义

保留原版本可能是正确结果；候选被拒绝也可能提供有价值的改进经验。相反，框架成功返回最佳候选，只能说明内部协议选出一个产物，不自动证明部署收益、语义正确性或长期复利。
